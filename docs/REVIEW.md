# sbox-reality 分支审查与修复方案

审查分支：codex/multi-tenant-traffic
审查提交：d478b92
首轮审查方式：静态审查；后续已在 Windows Portable Git Bash 运行回归测试，未进行真实 Linux VPS 集成验证。以下是首轮确认的问题，不代表完整审计。

## 1. P1：交互菜单等待输入时阻塞流量检查
位置：sbox-manager.sh:872-919、119-125。
manager_menu 进入时取得 fd 9 的 flock，整个菜单循环不释放。用户只要停留在菜单，systemd 的 traffic check 就会在等待锁 60 秒后失败，额度及到期限制不能及时更新。
修复：读取用户输入时不持锁，仅对实际状态操作持锁；避免节点选择等交互等待也占锁。
验证：菜单停留在输入提示时，另一个进程仍能完成 traffic check；并发写操作仍互斥。

## 2. P1：OpenRC 守护进程终身持锁
位置：sbox-manager.sh:1725-1738、1497-1503。
traffic daemon 进入无限循环之前已在 main 中取得锁，因此其他 node/traffic 命令在 flock 可用时持续超时。flock 缺失时 acquire_lock 又静默跳过互斥。
修复：每轮检查单独持锁并在休眠前释放；明确提供并验证锁依赖，不能无锁写状态。
验证：守护进程休眠期间可执行管理命令；两次检查不能并发写状态。

## 3. P1：端口修改/删除失败后暂停规则丢失
位置：sbox-manager.sh:943-987、387-413。
端口修改和删除都先清理旧防火墙规则，再调用可能失败的配置检查和服务重启。回滚仅恢复 nodes.json/config.json，不恢复旧端口的暂停与计数规则。已耗尽额度或到期的节点可能重新可用，直到后续成功检查。改端口还会丢弃尚未采样的流量。
修复：变更前采样并保存计数；为规则变更建立失败恢复路径，配置验证失败不改变现有规则；服务失败回滚后立即恢复旧限制。
验证：注入配置校验失败/重启失败，旧配置和旧端口限制保持一致；端口迁移前后的累计用量不减少。

## 4. P2：Telegram 通知失败中断后续节点检查
位置：sbox-manager.sh:1325-1327。
恢复通知直接调用 notify_node，未像其他通知一样处理失败。启用 set -e 的独立 traffic check 执行中，如果没有 Telegram 配置或发送失败，检查会退出，后面的节点不再检查。
修复：通知失败不影响限制执行和后续节点检查；单独保留通知失败信息。
验证：首个节点恢复时令通知失败，后续到期节点仍被暂停。

## 5. P2：额度单位 E 被接受但按字节计算
位置：sbox-manager.sh:67-84。
正则接受 E、EB、EiB，但乘数分支只处理到 P，导致 1E 被保存为 1 字节，而非拒绝或正确换算。
修复：额度解析仅接受有实现且处于安全数值范围的单位和数值，超范围明确报错。
验证：覆盖正常单位、1E、超大值和小数，防止错误额度导致误暂停。

## 当前版本状态

2026-10-22 修复了上列五项问题，并补充修复了删除节点后服务端入站残留的问题：

- 合并配置时使用变更前后受管 tag 的并集，删除节点会同时删除其服务端入站，保留自定义入站。
- 菜单输入和 OpenRC 守护进程休眠期间不持锁；每次命令单独互斥，缺少 flock 时明确失败。Debian/Ubuntu 安装 util-linux，Alpine 显式安装 flock 子包。
- 配置验证通过后才准备新端口规则；新监听启动前先应用必要的暂停规则，旧规则保留到重启成功。失败时恢复配置、流量状态和端口限制。
- 改端口前后采样旧端口计数，计数读取同时匹配节点 ID 和端口，防止新旧端口规则共存时重复累计。
- 恢复通知失败只记录警告，继续检查后续节点；额度拒绝未实现的 E 单位和超出精度范围的数值。
- 安装支持 --version 固定版本；升级事务在程序替换前建立快照，失败时尝试恢复程序、运行文件和原服务状态。

新增 tests/test-manager-reliability.py 和 tests/test-install-version.sh 已接入 CI，覆盖删除、配置/重启故障、UDP 防火墙故障、计数迁移、锁作用域、通知失败和安装回滚。原节点管理测试新增断言：被删除节点的服务端入站必须消失。

验证范围仍需区分：自动化回归中的防火墙和服务操作使用隔离替身，不能代替真实 Linux VPS 的联网、实际流量计数和 systemd/OpenRC 集成验证。Debian/Ubuntu 失败回滚恢复文件，不回滚 dpkg 软件包数据库；脚本会明确提示重新安装所需版本来同步软件包状态。普通配置仅包含 inbounds；WARP 仍按需添加配置。
